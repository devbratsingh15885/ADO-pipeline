Eg: Suppose one new ticket came to create VM (Explains the steps)
Clone parent module from Azure repository 
Create one feature branch - vm creation-ticket2035 
- message - add one VM in tfvars in map of object
- Post addition- push the code to feature branch - remote repo
- As soon as we push the code to remote feature automatically pipeline will run (YAML)
- Before generation of plan it will validate or scan using code - tfsec (vulnerabilities), trufflehog(secret management), tflint (linting process), Chef, blackaqua, checkops, 
- If Everything looks good and plan is succeded then only reviewer can approve and merge this pull request (pr) to main branch. 
- as soon as it gets merged, automatically pipeline will run from main branch, against check ups with best practices Azure devsecops best practises with security tools - tfsec (vulnerabilities), trufflehog(secret management), tflint (linting process), Chef, blackaqua, checkops, 
- if all security, testing, linting checks are passed, it goes to plan stage and post plan it goes to manual validation stage
- Once lead checks up this manual validation stage, once he approves, apply will happen and VM will be added.
